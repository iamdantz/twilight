# Contributing

Twilight is at the definition stage. The palette, the rules and the documents in this repository are what is being built. There are no application themes yet.

## What is useful right now

- **Errors in the numbers.** If a value in [design-system.md](docs/design-system.md) or [palette/twilight.json](palette/twilight.json) does not meet the contrast it claims, open an issue with the two colors and the ratio you measured.
- **Gaps in the rules.** If you tried to map Twilight onto a tool and a region had no clear role, describe the region and the tool.
- **Questions about the method.** If a step in [construction.md](docs/construction.md) is unclear or looks wrong, ask.

## Proposing a change to a color

Colors are not adjusted by eye. A proposal should name the rule it changes, or the parameter in [construction.md, section 12](docs/construction.md#12-parameters-decided-vs-derived), and show that every guarantee in [design-system.md, section 14](docs/design-system.md#14-guarantees) still holds afterwards. A guarantee may go down only under the conditions in [construction.md, section 10.1](docs/construction.md#101-quality-floors): never below its category minimum, named in the changelog, and with a loss that is imperceptible or well inside the standard.

## Before opening a pull request

Run the `twilight-auditor` skill on your branch and include its report. It must return APPROVED. Palette, rules, documents, version and changelog are audited together; what it checks is defined in [the skill](.agents/skills/twilight-auditor/SKILL.md).

Every pull request to `main` also runs the [Validate workflow](.github/workflows/validate.yml):

- **validate** runs the skill's validator against the base branch, rebuilding every flavor. It must pass before merging. The report is in the job summary.
- **robust** rebuilds with twice the optimizer restarts when the change touches `construct.py`, `validate.py`, `requirements.txt` or the palette.
- When the change edits the validator, the base branch's copy also runs on it. That step never blocks; a difference there needs a reviewer to confirm that no check was loosened.

The same checks run locally with `python .agents/skills/twilight-auditor/scripts/validate.py --compare main`, adding `--robust` for construction changes. The workflow does not replace the audit. A passing validator is necessary but not sufficient.

Pull requests are merged with a merge commit or a rebase, so each version stays its own commit.

## Versions

- **Patch**: wording, documentation fixes, tooling.
- **Minor**: added rules or tokens, and values regenerated by the documented method after a change to the method.
- **Major**: a token removed or renamed.

`palette/twilight.json` carries the version of the latest CHANGELOG entry.

## Building a theme for a tool

Not accepted yet. When ports open, they will follow [Applying the system](docs/design-system.md#12-applying-the-system) and use the naming *Twilight {Flavor}*, with Afterglow as the accent.

## Writing

Documents are in English. Keep sentences short and claims measurable.
